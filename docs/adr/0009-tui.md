# ADR-0009: Interactive terminal UI

- **Status:** Accepted
- **Date:** 2026-11-20
- **Source:** 392 code comments as of `5f17242`, moved here by [ADR-0001](./0001-record-decisions-in-adrs-not-comments.md)

## Context

The interactive mode is an Ink (React for the terminal) application. Terminal rows are a hard budget, input arrives as raw key and mouse sequences, and the UI must stay responsive while syncs run in the same process.

## Decisions

Grouped by the file that implements them, source before tests. Each entry names the symbol it governs.

### `src/components/App.tsx`

- **AppProps.onSyncRepository**: onSyncRepository is optional on App; when it is absent the fuzzy switcher does not offer its per-repository sync key (s).
- **AppProps.copyToClipboard**: copyToClipboard is optional on App; when it is absent the fuzzy switcher does not offer its copy key (y).
- **App.addLog**: Log lines arrive in bursts (a sync of many repositories logs dozens per second), and appending each one copied the whole log buffer and re-rendered the tree. App collects incoming lines in a ref and flushes them in one state update every LOG_FLUSH_INTERVAL_MS.
- **splitLogLines**: The log panel budgets one row per entry, but some messages contain newlines (the debug timing table, sync summaries) and Ink renders each as its own row, overflowing the terminal and forcing full repaints. splitLogLines splits messages into one entry per line rather than flattening them, and drops only leading and trailing empty lines, since Logger.table wraps its content in newlines and keeping them would waste scarce rows and inflate the entry count.
- **App**: Interactive operations such as branch or worktree creation run independently of sync and queue behind it, so App tracks them in a separate activeOps list instead of letting them drive the sync status spinner.
- **App.setStatus**: App mirrors sync status in a ref that the progress listener reads synchronously, so progress rows arriving while idle are dropped and each new sync starts with an empty progress list.
- **App**: In App, l folds the log panel to one line and + / - move the boundary between the log and the repository table. A null rows preference means the repository table takes the rows it needs first and the log gets the rest.
- **App**: When a key cannot act right now (for example s during a sync), App briefly shows a notice in place of the key legend instead of silently doing nothing.
- **App**: The l key only undoes a fold the user made; when the log panel was folded automatically for lack of room, only + brings it back (at the repository table's expense).
- **App.describeRunningWork**: Quitting waits for a running sync but terminates running hooks and abandons any worktree still being created, so App lists syncs, active operations and running hooks when asking the user to confirm a quit.
- **App**: Ink delivers mouse reports to every useInput handler; App ignores them so that only the scrollable log panel acts on them and no keyboard shortcut fires from a stray click.
- **App**: Once a quit is under way, a second q is InteractiveUIService's force-quit shortcut, so App passes it straight through instead of showing the running-work warning again.
- **App**: Pressing + restores a log the user folded with l at its previous size; a log folded for lack of room comes back at the smallest panel size, taken from the repository table.
- **App**: Pressing - folds the log to one line when shrinking would go below the smallest panel or would not change the layout because the repository table already has every row it wants.
- **App**: The updateLastSyncTime event only records a timestamp and must not end the sync. The service stamps Last Sync from inside a cycle, so with overlapping cycles the first to finish would reset the status bar to Idle and re-arm the s/x/r guards while another cycle was still running; setStatus, driven by the service's count of in-flight cycles, is the single gate.
- **App**: Open repository pickers hold indexes into the repository list, so App closes them when the configuration is reloaded and the list changes.
- **App**: App reads the repository list once per opened modal via useMemo. Re-reading it every render gave modals a fresh array on every log line and progress event, re-running every effect keyed on it; a reload closes the pickers and changes the memo key.
- **App**: reloadGeneration is listed as a dependency of the repository-list memo without being read, as a signal that a configuration reload changed the list.
- **App**: StatusBar is memoised, so App memoises the active operation labels; a fresh array each render would defeat that memo on every log flush.

- **FuzzySwitcherProps.copyToClipboard**: When copyToClipboard is not provided, FuzzySwitcher does not offer the copy action.

- **FuzzySwitcher**: Editing the FuzzySwitcher query resets the selection to the best match, because a changed query re-ranks every entry.
- **FuzzySwitcher**: Opening the FuzzySwitcher action menu pins the selected entry by key, so a repository that finishes loading while the menu is open cannot re-rank a different entry under the actions.
- **FuzzySwitcher**: The FuzzySwitcher list reserves four rows (the query line and the gap under it, the gap above the path line and the path line) plus one each for the message and failure lines when shown. The count must match the rendered lines.
- **FuzzySwitcher**: FuzzySwitcher's action menu shows one row per action when the terminal has room and otherwise puts all actions on one line, so the menu never pushes the status bar off the screen.

### `src/components/HelpModal.tsx`

- **HelpModal**: Quit is bound to q only, not Esc. Esc is the interface's back-out key (closes help, cancels or steps back a wizard), so also binding it to exit would let one extra Esc or a key repeat tear down the daemon and the hooks it has running.
- **HelpModal**: HelpModal's compact layout spends 6 rows outside the help lines: the border (2), the title and its margin (2), and the footer and its margin (2). The roomy layout adds outer margins (4) and vertical padding (2), totalling 12.
- **HelpModal**: HelpModal shows the whole help sheet with spacing when the terminal has the rows, falls back to a compact layout without spacing, and scrolls when even the compact sheet does not fit.
- **HelpModal**: HelpModal reserves the 'more above' and 'more below' rows as soon as the sheet scrolls, so the visible window does not change size under the reader.
- **HelpModal**: Ink delivers a terminal mouse report as a single input string, so HelpModal ignores mouse sequences in its input handler so that scrolling never registers as a keystroke.

### `src/components/layout.ts`

- **layout**: Modal sizes are computed from the terminal rather than fixed widths and list heights, because a fixed box clipped its border on narrow terminals and pushed the frame past the screen on short ones, at which point Ink stops rendering incrementally and repaints everything on every update.
- **COMPACT_MODAL_BELOW_ROWS**: Below 30 terminal rows, modals drop their outer margins and vertical padding, because on a 24-row terminal those four rows are most of what the modal's list would otherwise get.
- **MIN_MODAL_WIDTH**: Modal boxes never shrink below 24 columns, because below that nothing inside is legible anyway.
- **MODAL_FRAME_COLUMNS**: A modal box spends 6 columns outside its content: the 2-column border and paddingX of 2 on each side.
- **useModalLayout**: Every modal spends 6 rows outside its content: border (2), title and margin (2), footer and margin (2). Unless compact it also spends its outer top and bottom margin (2) and paddingY (2), totalling 10.
- **useModalLayout**: useModalLayout's availableRows is the row count App has left after drawing the status bar; a modal rendered on its own, with no availableRows, gets the whole terminal height.
- **listRowsFor**: A list that fits is shown whole; one that does not gives up two rows to its '...' markers, reserved up front so the visible window does not change size as the selection moves.
- **isListUp**: Ctrl-P and Ctrl-N move through wizard lists as in a shell or editor so hands stay on the home row; they never conflict with filters because filters only accept input that arrives without Ctrl.
- **DASHBOARD_CHROME_ROWS**: The repository table spends 3 rows outside its repository rows: the border (2) and the column headings (1).
- **LOG_MIN_ROWS**: The smallest log panel worth drawing is 4 rows: the border (2), its heading (1) and one log line.
- **LOG_COMFORT_ROWS**: Unless the user resizes the log with + or -, the repository table never squeezes the log panel below 8 rows.
- **LogSizePreference**: A LogSizePreference rows value of null means no explicit + / - size: the repository table takes the rows it needs first and the log gets the rest.
- **homeLayout**: homeLayout gives the repository table priority, since it is the home screen, but by default leaves the log a readable panel. When there is no room for both a table row and a log panel the log folds to one line, and below that the table is hidden.
- **homeLayout**: homeLayout hides the repository table entirely when it would have no repository rows, since a border and headings alone are not worth the rows.
- **homeLayout**: When the default even split would leave the repository table with no rows but it still fits beside a folded log, homeLayout folds the log rather than drop the table. An explicit + / - size is kept, because that is how the user lets the log take the whole screen.
- **DROP_ORDER**: As the terminal narrows the repository table drops columns in the order next, worktrees, changes, age, result; the state and name columns always stay.
- **dashboardColumns**: dashboardColumns first shrinks the result column, then drops whole columns in DROP_ORDER, and every cell truncates, so each repository row stays on one line at any terminal width.

### `src/components/LogPanel.tsx`

- **WHEEL_LINES**: One mouse wheel notch scrolls the log panel 3 lines, matching what most terminals send per detent, so a flick covers ground without overshooting.
- **ScrollState**: Following the log tail and parking at an offset are one piece of reducer state, because every position implies whether new entries should pull the view along; separate states had to be written together from one keystroke, with one computed inside the other's updater, which must be pure since React may re-run updaters. The offset is only meaningful while parked; in follow mode the render derives it from the current maxOffset so a resize or burst of entries can never leave the view past the end.
- **scrollReducer**: Scrolling the log panel down onto the last line re-enables following the tail, because the reader chose to come back.
- **useLogScroll**: The log scroll state is held by App via useLogScroll, so the position survives the log panel being unmounted while a modal is shown.
- **LogPanel**: The 'N more above/below' indicator rows count against the panel height; drawing them on top of a spent budget made the panel one or two rows taller than asked, the App frame outgrew the terminal and Ink repainted the whole screen each render. Both indicator rows are reserved as soon as the log is longer than the panel, not each as it appears, because a viewport size that depended on the scroll position would move maxOffset under the reader and break the wheel up/down round trip.
- **LogPanel**: At the smallest height App hands out, only one row is left after the header and one log line, and two indicator rows drawn there overwrote the header. Below that height both counts share one row.
- **LogPanel**: The log panel's scroll offset is derived at render, never stored: following always renders the tail, and a parked offset is clamped to what the panel can currently show.
- **LogPanel**: LogPanel supports vim motions, arrows and the mouse wheel. Ink delivers a whole mouse report as one input string, so wheel events are parsed inside useInput rather than through a separate stdin listener.
- **LogPanel**: LogPanel renders at a fixed height with overflow hidden. The row budget keeps the normal frame inside it, and clipping bounds what the budget cannot predict (an entry still carrying a newline, a message Ink wraps), so the frame never outgrows the rows App reserved.
- **LogPanel**: The log panel heading truncates rather than wraps at any width, so it always occupies exactly one row and never pushes into the log lines below it.
- **CollapsedLogLine**: When the log is folded, CollapsedLogLine shows the entry count and latest entry so an error still shows while the repository table has the screen. Its expand key hint is l when the user folded the log and + when it was folded for lack of room.
- **LogPanel**: LogPanel is memoised because status and progress events re-render App without changing the log, and the custom comparator is required: a bare React.memo of a function component becomes a simple-memo fiber, and React 19.2 only refreshes useEffectEvent handlers (which Ink's useInput uses) for plain function components, so keys would run a stale handler (gg stopped working). Supplying a comparator keeps the component an ordinary function fiber under the memo boundary.

### `src/components/StatusBar.tsx`

- **StatusBar**: StatusBar shows its full key legend only when the terminal is wide enough and otherwise shows the keys alone, because a legend Ink wrapped onto a second row made the bar taller than App budgets for and pushed the top of the screen off.

- **StatusBar**: StatusBar builds a fresh schedule array on every render, so the next-sync memo compares a joined string key instead of the array.
- **StatusBar**: StatusBar bumps a tick state just after each scheduled run time so the displayed Next Sync never lags behind the clock.

- **StatusBar**: Every status-bar line truncates rather than wraps, because App budgets exactly one terminal row per status line.
- **StatusBar**: StatusBar is memoised because App re-renders on every log flush and none of that affects the bar.

### `src/services/InteractiveUIService.tsx`

- **InteractiveUIService options.debug**: The --debug flag given to the interactive UI is forced onto every repository, including repositories a config reload loads later.
- **InteractiveUIService constructor**: The interactive UI's maxRepositories is the parallelism setting, not a display value; the progress pane is sized from it because it wants one line per concurrently syncing repository, but disk walks are I/O and must never be widened by lengthening a pane.
- **InteractiveUIService.setRepositoryFilter**: The CLI's --filter is stored on the interactive UI because a config reload rebuilds the repository list from the file and would otherwise silently widen a filtered session to every repository.
- **InteractiveUIService.createServiceLogger**: Services the UI owns are built with the panel logger already in their config, because while Ink holds the alternate screen a console line would be drawn over the interface, and sub-services copy the logger at construction.
- **InteractiveUIService.subscribeToProgress**: Progress subscription is a separate method so a service can be watched before it joins syncServices, because a reload's initialize, which can run a clone, is the longest wait in the interface and reports through the progress emitter.
- **InteractiveUIService.start**: Every repository action from the TUI goes through the RepositoryOperations facade, never through a sync service's GitService directly.
- **InteractiveUIService.start**: Mouse tracking is enabled after render has entered the alternate screen and disabled in destroy after Ink restores the primary buffer, gated on stdout being a TTY like Ink's alternate screen, since a DECSET written down a pipe is just stray bytes.
- **InteractiveUIService.start**: Ink 7 handles Ctrl+C at its root before any useInput listener, dropping raw mode and unmounting without calling onQuit, cancelling cron jobs or exiting, which left the process syncing headlessly. The Ink exit promise is the only signal independent of which modal owns the keyboard, and it also fires after a render error; resolve and reject both route to the same handler.
- **InteractiveUIService onInkExit**: The Ink exit handler compares against the current instance rather than checking for null, because destroy nulls this.app while unmounting and Ink settles its exit promise a tick later, so that arrival is our own teardown reporting back.
- **InteractiveUIService onInkExit**: Ctrl+C while a q shutdown is waiting is treated as the second press and forces the quit, because Ink tears its tree down and would otherwise leave the user staring at a bare terminal while the wait runs on.
- **InteractiveUIService.handleSyncRepository**: The repository switcher's single-repository sync runs through the same cycle machinery as a full sync, so it claims the repository, drives the status bar and records its outcome identically.
- **InteractiveUIService.handleSyncRepository**: The repository index is validated because a reload between opening the switcher and pressing s can shrink the list.
- **InteractiveUIService.handleReload**: A reload runs its own sync, so it is a cycle for the status bar and may overlap another; its idle transitions are tied to that cycle so one finishing cannot blank the other's progress or re-arm the s/x/r guards mid-fetch. The cycle is opened before the wait so every exit path, including a missing config file, closes it exactly once.
- **InteractiveUIService.handleReload**: A reload validates and loads the new config and initializes its services before cancelling old cron jobs, so a validation failure never leaves a window with no cron running.
- **InteractiveUIService.handleReload**: When a reloaded config leaves the --filter matching nothing, the reload fails with a filter-specific error instead of No repositories could be initialized, which would blame the repositories; the old services and cron jobs stay in place.
- **InteractiveUIService.handleReload**: Reloaded services get their panel logger before construction because initialize logs fetch progress, metadata repair and probe failures through the logger each sub-service received at construction.
- **InteractiveUIService.handleReload**: Reloaded services are subscribed to progress during initialize because a clone reports through the emitter and normal subscription only happens after every initialize resolves; the temporary subscription is dropped afterwards, survivors are re-subscribed and failed services discarded.
- **InteractiveUIService.handleReload**: A failed repository's name comes from the repositories array at the same index, since allSettled preserves order and a rejected init never returned a service, while the git error text names nothing the user can find in the config.
- **InteractiveUIService.handleReload**: If q was pressed while the new config loaded, the reload is abandoned, because the shutdown already released cron jobs and is waiting on visible syncs, and swapping in and syncing new services would outlive that wait.
- **InteractiveUIService.handleReload**: After a reload, cached disk usage for the new services' paths is invalidated, because initialize can clone or create worktrees and a cycle where every repository is skipped never rebuilds the header total.
- **InteractiveUIService.handleReload**: Reloaded services are not passed through injectLoggersIntoServices because they were built with their panel logger; injecting again would create a second Logger and leave config.logger pointing at a dead one. Startup still injects because services exist before the UI's panel.
- **InteractiveUIService.shutdownNotice**: Shutdown progress lines are written to the output stream as well as the log panel, because on the Ctrl+C path Ink has already restored the primary buffer and the panel is gone, so the process would otherwise look hung.
- **InteractiveUIService.writeLines**: Teardown's stream writes go through one guard for a stream that refuses a write outright (stdout is injected and not always a TTY), not for EPIPE which arrives as an error event; it ensures a refusing stream does not abandon the rest of teardown, which restores the terminal.
- **InteractiveUIService teardown**: An error raised after the UI has been torn down is dropped: there is no longer a surface to report it to.
- **InteractiveUIService.requestForceQuit**: The force-quit shortcut ignores presses within FORCE_QUIT_GUARD_MS of starting shutdown, because a held key repeats every few tens of milliseconds and the shortcut must be a second deliberate decision.
- **InteractiveUIService.destroy**: A second destroy call while the first is waiting, from a second q or the SIGINT a second Ctrl+C becomes after Ink drops raw mode, shortcuts the wait instead of starting a new teardown and returns the shutdown in flight so every caller settles on the same one.
- **InteractiveUIService.runShutdown**: isDestroyed is set after waiting on in-progress syncs, not first, because it silences addLog and setting it early hid the waiting and data-loss notices so the interface appeared frozen for up to 30 seconds.
- **InteractiveUIService.runShutdown**: Hook cleanup runs before isDestroyed silences addLog so users are told which in-flight hooks were killed, with the lines repeated to the stream because the panel is torn down moments later. It is awaited because the exit closes the hooks' pipes, so a hook trapping SIGTERM only gets to act while cleanup holds the process open.
- **InteractiveUIService.runShutdown**: Mouse tracking is disabled after Ink's unmount because Ink writes the alternate-screen exit inside unmount and treats earlier output as disposable, so the disable sequence must land on the restored primary buffer. It sits outside the unmount branch because on the Ctrl+C path Ink already unmounted itself while this.app still names that instance.

### `src/services/progress-emitter.ts`

- **ProgressEmitter.emit**: ProgressEmitter iterates over a snapshot of its listeners so a listener that unsubscribes a sibling during emit does not cause that sibling to miss the current event.
- **MAX_PHASE_ITEM_EVENTS**: Each phase stage reports every item up to 100 events and samples every step-th item beyond that, so a repository with thousands of branches does not cause thousands of TUI re-renders and MCP notifications. The first and last items always report, the first so a large phase does not show its opening message for dozens of items and the last so the stage ends on processed equal to total.
- **trackPhaseItems**: trackPhaseItems is called where each item finishes, not where it is dispatched, because items run concurrently and counting completions keeps the sequence moving forward; the counter is read and written with nothing awaited between, so every event carries a higher processed value than the last.
- **trackPhaseItems**: Progress emission inside trackPhaseItems swallows errors, because callers attach it to the item's own promise and a throw would turn a finished item into a failed one, such as a failed prune status check that skips a removal.

### `src/services/repository-dashboard.ts`

- **RepositoryDashboard**: RepositoryDashboard records per-repository state as events happen (sync start or settle, status view checks), so drawing the home table never costs a git process.
- **RepositoryDashboard.records**: Dashboard records are keyed by repository name, which the config keeps unique, so a reload that rebuilds every service keeps each repository's history.

- **RepositoryDashboard.refreshWorktreeCount**: The dashboard runs one git worktree list per repository per sync, never per render, and keeps its last figure if the listing fails.

- **RepositoryDashboard.recordWorktreeStatus**: Worktrees whose status probe failed are excluded from the dashboard tallies, since they say nothing about either count.

### `src/services/repository-operations.ts`

- **splitBranchSuffix**: The branch wizard submits the name it displayed, so a taken name x arrives as x-1; the trailing -<n> is split back off so the suffix walk continues x-2, x-3 instead of x-1-1. The digit count is bounded so an absurd suffix cannot be incremented past the point where the name stops changing.
- **RepositoryOperations**: RepositoryOperations holds everything the TUI does to a repository besides syncing (branch creation and publishing with rollback, worktree creation, status and disk views, diverged cleanup, force clean). The TUI reaches git only through it, never through a sync service's GitService, so lock queueing and clone-mode branching live in one place.
- **RepositoryOperations.getBranchesForRepo**: Clone-mode branch listing goes to the network via ls-remote whether or not the clone is initialized, so failures return an empty list in both cases and the wizard's fetch-and-retry path handles them uniformly.
- **RepositoryOperations.getDefaultBranchForRepo**: A failure resolving the default branch is logged, because the wizard swallows it to keep the branch list on screen, and the remote's message is what tells the user to set branch explicitly.
- **RepositoryOperations.createAndPushBranch**: The new branch's commit is read before the push so a failed push's rollback can compare-and-swap on the commit this attempt created.
- **RepositoryOperations.createAndPushBranch**: The collision suffix walk continues from the submitted name rather than restarting, because the wizard submits the displayed name and appending to it would produce x-1-1.
- **RepositoryOperations.createAndPushBranch**: The branch creation result names the branch actually attempted, which differs from the requested name after a suffix walk.
- **RepositoryOperations.createAndPushBranch**: An already-exists error does not trigger a suffixed retry when it is an UnpushedBranchLeftoverError, because retrying would orphan the unpushed branch locally while creating a suffixed one and discard the only message telling the user.
- **RepositoryOperations.rollbackUnpushedBranch**: When a new branch's push fails, the local branch is deleted so the wizard's retry with the same name does not collide with the leftover and quietly create name-1. The delete is a compare-and-swap on the creation commit so a ref moved by something else is left alone, and a leftover that could not be removed is named in the message.
- **RepositoryOperations.rollbackUnpushedBranch**: A stale info rejection from the create-only lease means the ref exists on origin after all, so it is phrased as an already-exists collision, which also sends the creation loop round again with a suffixed name.
- **RepositoryOperations.rollbackUnpushedBranch**: A leftover-branch message names the bare repository path, because it lives under .bare/<repo> where the user never stands, so a bare git branch -D instruction would work nowhere they would run it.
- **RepositoryOperations.getWorktreeStatusForRepo**: The home screen's dirty/unpushed column is the status view's result remembered, not a separate probe, and it is recorded only while the index still names the same service, since a reload during the check can hand the index to another repository.
- **RepositoryOperations.deleteDivergedDirectory**: After deleting a diverged directory, cached disk figures for it and its worktree directory are invalidated, because otherwise the status view would show the old total for a whole cache TTL, even across reopening the modal; the header total rebuilds on the next cycle.
- **RepositoryOperations.forceClean**: Force clean results are also written to the log because the modal truncates result lines once they scroll.

### `src/services/sync-cycle-scheduler.ts`

- **SyncCycleHost.isShuttingDown**: SyncCycleHost.isShuttingDown turns true once quitting has begun, and from then on the scheduler starts no sync cycle and arms no cron job.
- **SyncCycleHost.notice**: SyncCycleHost.notice exists separately from log because messages about waiting on in-progress syncs must reach the user even after Ink has released the screen during shutdown.
- **SyncCycleScheduler.setupCronJobs**: setupCronJobs does nothing once shutdown has begun, because a reload (or its failure path) that was already past its checks when quit was pressed would otherwise re-arm jobs the shutdown just released and keep the daemon syncing while it exits.
- **SyncCycleScheduler.cancelCronJobs**: Cron tasks are released with destroy() rather than stop(), because node-cron keeps every scheduled task in a module-level registry freed only on `task:destroyed`; with stop() each reload leaked a whole generation of WorktreeSyncService objects and their git clients. destroy() may return a promise that rejects after a 5s timeout (node-cron 4.6), so the promise is caught and logged to avoid an unhandled rejection.
- **SyncCycleScheduler.waitForInProgressSyncs**: The wait for in-progress syncs is converted to a settled outcome before racing it against force-quit, because the timeout rejection still arrives after force-quit wins and an unhandled rejection would crash the process while exiting.
- **SyncCycleScheduler.beginSyncCycle**: The syncing/idle status is reference-counted across overlapping sync cycles: the first cycle to start sets 'syncing' and only the last one to finish sets 'idle'.
- **SyncCycleScheduler.runSyncCycle**: When a sync cycle is refused because shutdown has begun, the status is reset to idle if no other cycle is running, because the key handler already switched the status bar to 'syncing' for the key press.
- **SyncCycleScheduler.recordSyncOutcome**: recordSyncOutcome sets the last-sync outcome before returning early for an all-skipped cycle: such a cycle leaves 'Last Sync' unchanged, but the status bar must stop claiming the previous sync was OK.
- **SyncCycleScheduler.runSyncServices**: A sync that returns started=false never owned the repository, so it does not emit the 'complete' progress event: the visible row belongs to whoever holds the repository (another cycle, process, or interactive operation) and closing it would remove it mid-fetch. Every other outcome, including a thrown sync, closes its row.
- **SyncCycleScheduler.runSyncServices**: Each repository's dashboard row is settled as soon as that repository finishes rather than when the whole cycle does, via a separate promise branch so the rejection is still counted by the cycle's Promise.allSettled.

### `src/services/terminal-launcher.ts`

- **LAUNCH_FAILURE_WINDOW_MS**: Only a launcher that exits non-zero within the first five seconds is reported as a launch failure; one that exits later ran and was closed by the user, which is not a launch failure.
- **VIM_GUI_FLAGS**: The `-g` GUI escape hatch applies only to vi/vim, because it is a GUI flag only in vim's parser: nano and pico read it as --showcursor, helix as --grammar, emacs as --geometry, and nvim has no `-g`. The flag is therefore not read off arbitrary editors' argv.
- **TERMINAL_EXEC_FLAGS**: The set of known terminal exec flags is derived from the exec-flag table in TERMINAL_CONSTANTS so new emulator entries are recognized automatically. It is used to detect an exec flag the user already wrote into the override or $TERMINAL, where appending a second one would make it an argument to the first.
- **isTerminalEditor**: isTerminalEditor is a heuristic that deliberately fails open: an unrecognized editor is treated as a GUI editor so nothing that already works gets refused, and unknown terminal editors are caught by the early non-zero exit check instead. A flag overrides the basename only for the editor family whose parser defines it, and an explicit terminal flag beats a GUI flag (`emacs -nw` is refused even with `-g`, `vim -g` is not).
- **isTerminalEditor**: For emacs, only its tty flags (-nw, --no-window-system, -t, --tty) mark it as a terminal editor, since emacs opens a window by default. These flags are not checked for other editors because `-t` means 'edit where tag is defined' in vim.
- **TerminalLauncher**: TerminalLauncher's editor and terminal launches are all detached and unref'd, so their outcome is reported through the host's log rather than awaited.
- **TerminalLauncher.openEditorInWorktree**: EDITOR/VISUAL is split into command and arguments the way a shell would, because it may contain flags (e.g. `code -w`) or quoted paths with spaces, and spawn without a shell would treat the whole string as the binary name.
- **TerminalLauncher.openEditorInWorktree**: A set-but-whitespace-only EDITOR/VISUAL is reported as an error rather than falling back to the default editor, since silently substituting another editor is exactly what openEditorInWorktree is meant to prevent; unset or empty values already fall back to the default.
- **TerminalLauncher.openEditorInWorktree**: Terminal editors are refused instead of spawned, because a detached child with ignored stdio has no TTY and exits within seconds having drawn nothing, which would otherwise be reported as success. The suggested remedy mentions Terminal mode only if a terminal emulator actually resolves, since on headless hosts that advice would be another dead end.
- **TerminalLauncher.openEditorInWorktree**: The hint logged when the editor exits early deliberately avoids diagnosing the cause, because the same exit comes from a terminal editor, a GUI editor without a display, a bad flag or a missing library; the error line names the command and status.
- **TerminalLauncher.openEditorInWorktree**: openEditorInWorktree returns success once the detached child is launched, not when it is known to keep running; the later outcome is logged by reportLauncherExit.
- **TerminalLauncher.openEditorInWorktree**: The synchronous catch around spawn does not handle a missing binary: Node reports that as a child with no pid and an asynchronous 'error' event, logged by the error handler. Only invalid calls, such as arguments spawn rejects outright, throw synchronously.
- **TerminalLauncher.reportLauncherExit**: Detached launcher children are not awaited, which would hold the TUI open; an exit listener is attached instead. It costs nothing while the TUI lives, and after quit the host's log is a no-op, so a late exit cannot reopen a closed wizard.
- **TerminalLauncher.reportLauncherExit**: An early launcher exit is checked for a signal as well as a non-zero code, because a child killed by a signal reports code null; a code-only check missed crashing launchers (a segfault arrives about 3ms in with code null) after the wizard had already reported success.
- **TerminalLauncher.copyToClipboard**: Copying a worktree path to the clipboard (pbcopy, wl-copy, xclip or xsel) treats a missing tool as a normal failed result rather than an exception: the result says what was looked for and the path is written to the log so it is not lost.
- **TerminalLauncher.resolveTerminalLauncher**: The tmux command is wrapped in `sh -c` so emulators that exec their trailing argv as a program (`alacritty -e`, `kitty -e`) can run it, which means every launcher path needs an exec flag, always obtained from terminalExecArgs.
- **TerminalLauncher.resolveTerminalLauncher**: On macOS Ghostty cannot be launched directly from the command line, so it is started with `open -na Ghostty.app --args ...`.
- **TerminalLauncher.resolveTerminalLauncher**: When Ghostty is launched through `open`, the exec flag after `--args` belongs to Ghostty, so it is looked up for `ghostty` in the same exec-flag table as every other emulator.
- **TerminalLauncher.terminalExecArgs**: All launcher paths (override, $TERMINAL fallback, candidate probe) use one exec-flag lookup so they cannot disagree about an emulator's flag. If the user already wrote an exec flag it is kept and no second one is appended, since it would become an argument to the first.
- **TerminalLauncher.parseCommandString**: Command strings are split the way a shell would so quoted paths keep their spaces. An unterminated quote is closed at end of string so a typo yields a best-effort argv instead of silently dropping the setting.

### `src/utils/clipboard.ts`

- **CLIPBOARD_TIMEOUT_MS**: A clipboard helper that neither exits nor fails within 3 seconds is treated as stuck (for example an X selection owner waiting on an unresponsive display), so the TUI never waits on it longer.
- **clipboardCommands**: macOS uses pbcopy; on Linux wl-copy goes first under a Wayland session, then xclip and xsel. Missing tools are skipped at spawn time, so the order is a preference rather than a probe.
- **clipboardCommands**: Without a Wayland session the X11 tools are still tried even if DISPLAY looks unset, because SSH X forwarding can set DISPLAY late; a headless host ends with an error message rather than a hang because each attempt is time-bounded.
- **runClipboardCommand**: Completion is detected on the child's exit event, not close, because xclip and wl-copy fork a child that keeps serving the selection and holds the stderr pipe open until something else is copied. The stderr stream is destroyed on exit for the same reason.
- **runClipboardCommand**: A clipboard tool that failed to start closes stdin, and the spawn error handler already reports that, so the stdin write's EPIPE is ignored rather than reported as a second failure.
- **copyToClipboard**: copyToClipboard uses the first installed clipboard command that works and never throws; when no tool is installed its error lists the tools it looked for so the user knows what to install.

### `src/utils/date-filter.ts`

- **filterBranchesByAge**: filterBranchesByAge reports an invalid duration through the caller's logger rather than console.warn, because under the TUI a bare console write lands on top of the Ink frame.

### `src/utils/disk-space.ts`

- **calculateSyncDiskSpace**: calculateSyncDiskSpace hands every directory to the measure callback at once, so any bound on concurrent walks belongs to that callback (the TUI passes DiskUsageCache's). A directory that cannot be measured counts as zero instead of failing the total; only a synchronous throw rejects, and the caller logs that through its own logger and shows N/A.
- **calculateSyncDiskSpace**: The du walks run concurrently because they are independent I/O; measured on a 197 MB six-directory workspace, six walks took 101 ms sequentially, 48 ms with DiskUsageCache(2) and 29 ms unbounded. The fan-out is left unbounded on purpose since the measure callback carries whatever bound the caller wants.

### `src/utils/disk-usage-cache.ts`

- **DiskUsageCache.size**: The status view reads disk usage through a TTL cache so reopening it does not repeat the walk the header just did. The cache is deliberately not keyed by mtime because a directory's mtime does not change when a deep file changes (measured on a 95k-path tree). Any walk already in flight satisfies the status view, since it is at worst as stale as the moment the view opened.
- **DiskUsageCache.refresh**: The header total bypasses the cache so it is as fresh as the sync cycle, and its walks refill the cache for the status view. A refresh joins only walks still queued behind the limiter, never ones already reading, because joining an earlier walk returned pre-mutation figures after a force clean and stamped them fresh for the whole TTL (measured overstating by 64 MB).
- **DiskUsageCache.invalidate**: Operations that shrink a directory themselves, such as deleting a .diverged/ entry from the status view, invalidate its cached size so the old total is not served for a whole TTL. In-flight entries are dropped too so a walk begun before the deletion cannot record its result afterwards.
- **DiskUsageCache.walk**: inFlight holds every running walk while queued holds only those the limiter has not dispatched, so the map a caller may join encodes the whole freshness rule. A rejected walk is never recorded, so the next caller retries instead of inheriting the failure for a TTL.
- **DiskUsageCache.walk**: Only the newest walk for a directory records its measurement; an older walk overtaken by a refresh or invalidation would otherwise write a figure that predates both.

### `src/utils/fuzzy.ts`

- **fuzzy**: The TUI switcher uses a small in-house subsequence matcher: query characters must appear in order, case-insensitively, and scoring rewards consecutive runs and word starts while charging for skipped characters. No library is used because the lists are a few hundred short labels and the matcher is linear per starting position.
- **PENALTY_LEADING_GAP**: A gap before the first matched character is penalised at a quarter of the normal rate so a query like main still finds repo › main and long repository names do not bury their own branches.
- **matchTerm**: Each occurrence of a term's first character is tried as a starting point and the best score kept, which lets main prefer the word main over the m of my-repo.
- **matchTerm**: If matching fails from one start position, no later start can succeed because it has strictly less text left, so the search stops there.
- **fuzzyMatch**: Whitespace splits the query into terms that must each match independently, the way fzf reads api feat; an empty or blank query matches everything with score 0.
- **fuzzyFilter**: Results are ordered by score, then shorter text, then original order, and an empty query returns the list as given.

### `src/utils/mouse.ts`

- **MOUSE_TRACKING_ENABLE**: Mouse tracking enables only button press/release with SGR reporting; motion tracking is deliberately off because only the wheel is needed and drag reporting would flood stdin and fight terminal text selection.
- **SGR_MOUSE_PATTERN**: Ink passes SGR mouse sequences to useInput with the leading ESC stripped, but the pattern also accepts the raw form so parsing does not silently break if Ink changes.
- **isMouseSequence**: Ink delivers unrecognized CSI sequences to useInput whole, so a mouse report arrives as one input string, and text-appending components must skip it or scrolls appear as garbage. The full report is matched, not a prefix, since typed characters arrive singly and pastes go through usePaste, so nothing typeable is mistaken for a mouse event.
- **parseWheelEvent**: parseWheelEvent returns null for clicks, horizontal wheel and non-mouse input so the caller's normal key handling still runs.
- **parseWheelEvent**: Modifier bits share the SGR button field, so only the low button bits are compared: 0 is wheel up, 1 wheel down, 2 and 3 horizontal.
- **createMouseTracking**: Mouse tracking is owned outside React because Ink's unmount sets its isUnmounted latch before tearing down the tree and then discards writes, so a cleanup effect could never disable tracking and the shell would inherit DECSET 1000/1006. disable is idempotent and also armed on process exit so uncaught exceptions and process.exit still restore the terminal.
- **mouse reporting teardown**: Disabling mouse reporting is best-effort: during teardown the output stream may already be destroyed.
- **createMouseTracking.enable**: enable marks tracking active and arms the exit listener before writing the enable sequence, so a stream that throws mid-write still gets a disable attempt on exit.
