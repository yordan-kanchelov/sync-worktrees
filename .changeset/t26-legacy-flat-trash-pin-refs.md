Trash entries created before pin refs were namespaced per workspace are recognized again. Those entries recorded a flat pin ref (`refs/sync-worktrees/trash/<id>`); the manifest validator added with the namespacing accepted, for a pinned entry, only `refs/sync-worktrees/trash/<workspace-hash>/<id>` (an entry with no pin at all was always fine), so after upgrading, every one of them read as an invalid manifest — hidden from `sync-worktrees trash`, rejected by `--restore <id>` with "no trash entry with id", never reaped, its payload holding disk and its pin holding objects through every `git gc`, and a warning about it repeated on every sync tick. Both layouts are now accepted, so those entries list, restore and age out normally, and reaping one deletes the flat pin named in its own manifest. The validator still requires the ref to sit under `refs/sync-worktrees/trash/` and to end at the entry's own id, so a hand-edited or corrupted manifest cannot point the reaper's `update-ref -d` at a branch ref or anywhere outside the trash namespace. The orphaned-pin sweep is unchanged — it still leaves flat refs alone, since it cannot tell one of its own from another workspace sharing the same bare repository (see README for what that leaves behind) — and the reaper now reports unrecognized trash content and legacy flat pin refs once per process instead of once per tick.
